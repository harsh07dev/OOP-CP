A chat server with the wiring left visible.

A multi-client console chat application: a threaded server, a JSON protocol, direct messages, rooms, and persistent history. Small enough to read, complete enough to use.

01

Build, start, connect.

From a clean checkout to two clients talking in three commands. The server listens on port 8080 by default.

a Build

cmake -B build -S . \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build --parallel

Requires CMake 3.15+, a C++17 compiler, and SQLite3.

b Start the server

./build/chat_server

# optional:
# ./build/chat_server 9090 \
#   ./chat_history.db

Logs go to logs/chat.log. Stop it with Ctrl-C.

c Connect two clients

# terminal 2
./build/chat_client

# terminal 3
./build/chat_client

Use 127.0.0.1 and port 8080 when prompted.

macOS: brew install cmake sqlite. Ubuntu / Debian: sudo apt install build-essential cmake libsqlite3-dev. Windows: build with CMake and MinGW-w64 or Visual Studio; see the README for details.

03

What to type.

Anything without a slash goes to public chat. Start with /help; the rest is here.

Command What it does
/usersList online users.
/msg <user> <text>Send a private message. Alias: /dm.
/create <room>Create a room and join it.
/join <room>Join an existing room.
/room <room> <text>Send a message to a room. Alias: /rmsg.
/historyShow recent public history.
/history dm <user>Show a direct-message conversation.
/history room <room>Show a room's message history.
/quitDisconnect and exit.
  • Protocol Newline-delimited JSON for v1. The original plain-text protocol still works for public chat.
  • Storage SQLite keeps public, direct, and room messages. Cursor pagination uses message IDs.
  • Tests Registration races, fragmented frames, privacy boundaries, room lifecycle, persistence, and the console client.
